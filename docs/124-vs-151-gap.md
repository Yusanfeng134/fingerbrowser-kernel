# 124 相对 151 缺什么（判断过，不是开关数差）

151 有 32 个 `fp-*` 开关，124 有 22 个，差 10 个。但**开关数不等于欠账**：有些是
外壳功能（124 不承载外壳），有些对应的问题在 124 上不存在。

逐项判断如下。方法是去 124 树里查实现点，而不是假定「151 修过的 124 也有」——
今天已经因为跨版本搬结论错过三次。

## 一、124 上不存在的问题（不用做）

| 项 | 为什么不存在 |
|---|---|
| **Accept-Language 漏点** | **实测线上头正确**：主文档/子资源/favicon 全为 `en-US,en;q=0.9`。151 的病因是 `ReduceAcceptLanguageUtils` 从 `intl.accept_languages` pref 重建头部，124 没有那套逻辑，已有的两处钩子（`GetAcceptLangs`、`ProfileNetworkContextService`）就够了。去掉 `--lang` 仍正确 → 钩子在起作用，不是死代码；不传 `--fp-accept-lang` 变回 `zh-CN` → 探针能失败，这个通过是真的 |
| **WebGPU 双分支泄漏** | 151 的 bug 是伪装被写在 `if (WebGPUDeveloperFeaturesEnabled())` 分支内部，web 路径拿不到。124 的伪装在构造时赋给 `vendor_`（`gpu_adapter.cc:156`），而双分支在 384 行、两边都读 `vendor_` —— 结构上不会漏 |
| `fp-platform-version` | 124 的 UA 元数据里 `platform_version` 走 `GetWindowsPlatformVersion()`，落点存在，**但这不是 124 特有的问题** —— 它和 151 一样泄漏宿主构建号。归到下面「真缺」 |

## 二、外壳专属，124 不需要（除非 124 也要当外壳）

`fp-shell`、`fp-pinned-url`、`fp-console-title`、`fp-newtab-url`、
`fp-account-panel`、`fp-account-initial`

这六个都是「客户端外壳」形态的东西：管理台地址栏、AI 新标签页、账号面板、钉标签。
124 目前只用于工作环境（店铺），不承载外壳，所以不是欠账。

**若将来 124 也要当外壳**，这六个连带 0016（Voyager 侧栏 + 垂直标签栏）一起才成立，
不是单独补开关能解决的。

## 三、真缺的（按危害排序）

### 1. `fp-passkey` —— 亚马逊安全密钥（危害最高）

151 的 0008。没有它，工作环境遇到 WebAuthn 风控时
`navigator.credentials.create()` **无限挂起**——不报错、不超时，用户只看到页面
卡住。这是客户当前会实际撞上的问题，不是理论缺口。

移植成本最高的一项：涉及 `content/browser/webauth/`、DPAPI 加密持久化、
`base/threading` 的 `ScopedAllowBlocking` 白名单。124 的
`VirtualAuthenticator` API 与 151 可能有差异，需要单独评估。

### 2. `fp-dpr-x1000` + 媒体查询同源 —— 指纹矛盾

124 的 `MediaValues::CalculateDeviceWidth` 同样走 `ScreenInfo`（`media_values.cc:156`
落点存在），而 `screen.*` 的伪装在 getter 上 —— **与 151 修前完全同构**。

这是**矛盾**而非未伪装：宿主 4K@175% 时媒体查询报 2195 而 `screen.width` 报 1920，
一条 CSS 媒体查询即可拆穿。危害高于单纯泄漏。

**未在 124 上实测**，只核对了落点存在。移植前应先跑
`probe/run-creepjs-audit.cjs`（需改 KERNEL 路径与开关名）确认矛盾真的出现 ——
不要因为「结构相同」就假定「症状相同」。

### 3. `fp-max-touch-points` —— 指纹矛盾

`navigator_events.cc` 落点存在。同样是矛盾（`maxTouchPoints=10` 而
`ontouchstart` 不存在）。

### 4. `fp-platform-version` —— 未伪装

泄漏宿主 Windows 构建号。危害低于上面两项（是未伪装而非矛盾），但移植成本极低
（单个函数加一个分支）。

## 四、建议顺序

1. **先在 124 上跑一遍审计**，确认第三节那几条矛盾真的出现。落点相同不等于症状
   相同——这正是今天三次误判的根源。
2. 矛盾类（DPR + 媒体查询、触摸）一起做：它们同根，且移植成本低。
3. `fp-platform-version` 顺带。
4. `fp-passkey` 单独评估：成本最高，且 124 的 WebAuthn API 可能有差异。

## 五、未核实的部分

本清单只对比了 `fp-*` 开关与几个关键落点。**没有**逐条比对 151 那 27 个补丁的
全部内容 —— 例如 0001（中文 Windows ACL）、0012（blink 生成器 UTF-8）这类构建
环境修复，124 是否需要取决于它的构建方式，未查。

也没有在 124 上跑过 `probe/` 下的任何脚本（路径与开关名都需调整）。
